# 本地摆位控制 v0.7.0

插件在游戏右上角提供 `PLAN`、`APPLY` 与 `UNDO` 三个按钮。

- `PLAN`：立即导出当前棋盘、背包和可见对手，启动独立的
  `BazaarLab.PlacementSearch` 进程，并显示准备、发现、复筛、终验进度，以及推荐物品、
  槽位和验证结果。搜索超过 15 秒会自动终止并给出提示。
- `APPLY`：再次核对计算时的完整物品实例、尺寸、区域、位置和 unlocked
  sockets；完全一致时才规划并逐条发送游戏原生 `MoveCardCommand`。
- `UNDO`：成功应用后，按经过验证的状态链逆序恢复。若玩家在应用后手动改过任意物品，
  撤销入口会作废，不会覆盖新的手工状态。

自动移动的安全约束：

1. 战斗中、拖动物品中、等待服务器时不执行。
2. 只移动到权威容器中连续、已解锁且空闲的槽位，不依赖游戏的挤出或交换行为。
3. 每条命令后等待服务器响应，并重新读取棋盘与背包；只有实际状态等于预期状态才发送下一条。
4. 任何手工变化、超时、物品消失或状态切换都会中止整条管线，旧推荐随即作废。
5. 需要借用背包作为临时空间时，必须先由玩家打开背包。
6. 搜索范围使用运行时读取到的实际已解锁棋盘槽位，不会再把尚未解锁的
   `Socket_0..9` 当作可用目标。

输出目录：`BepInEx/config/BazaarLab/`。每次计算结果使用带时间戳的
`placement-result-*.json` 保存，实际棋盘边界同时写入对应的
`placement-options-*.json`，便于复核。

部分执行失败时不会擅自自动回滚，因为服务器已经接受的移动不能可靠地视为数据库事务；
管线会立即停止并要求重新 `PLAN`。只有整条应用成功且状态未再变化时才开放显式 `UNDO`。
